GEMSDOE46 gemsdoe46-h46a-r8-conformal | split-conformal spacing r=8 px (800 m minimum separation), certified floor 0.0283 at 90.0% confidence (alpha=0.1000; n_cal=9 exchangeable spatial blocks; Lei et al. 2018 split conformal) | 39,108 dots | declared |G|=7905 px -> analytic ceiling 0.5588 | DTI on the catalogue proxy 0.0920 | geology: multi-scale L2 curvature + official tilt-angle edge layer; no feature uses distance to any known fault

The format rules, quoted from the official problem page

From the problem description, the submitted file must be:

  • “in the same projected coordinate reference system as the training data (projected coordinate system for UTM zone 11N, EPSG 32611)” — this file is EPSG:32611;
  • “at the same resolution as the training data (100m)” — 100 m pixels;
  • “the same bounds as the training data, and data outside the bounds is null or nan” — shape (3730, 3292), geotransform (100, 0, 243350, 0, −100, 4508550);
  • “a single layer with datatype of 32-bit float (float32) with values between 0 and 1 indicating the confidence or probability of fault presence” — single-band float32, minimum 0.0, maximum 1.0 in every cell of this file.

Quoted from the competition's own submission-format section. The organizer's summary, as quoted in the brief: “You can submit a single-band GeoTIFF (.tif) file, or a .zip file containing a single GeoTIFF, with your predictions. It must match the submission format's CRS, shape, and geotransform.” The form's optional Note field is described there as “A short comment to help you or your team tell submissions apart later e.g. clustering with k=25”.

If the form rejects the file

The portfolio has previously seen "Predicted values must be in range [0, 1]" on upload. That rejection cannot be reproduced from here (no account), and the primary file above is in [0, 1] in every cell — so if it happens again, upload the alternative encoding of the same dot set:

gemsdoe46-h46a-r8-conformal-nan.tif — identical positives (39,108), NaN outside the surveyed bounds, exactly like the organizer's sample_submission.tif.

The two files are provably identical under the official metric: FPw sums only over cells the prediction makes positive, and no dot is ever placed outside the footprint. The full account, including what is and is not verified about the rejection, is in IRREGULARITIES.md IR-46-02.

Why this file is unique

  • Generated from the official rasters only (all three sha256-verified on every run), by this repository's own feature stack, emitter and rule set. No raster, model weight, dot list or archive from any other submission was copied or reused.
  • The operating point is certified: r = 8 px has the largest split-conformal floor (0.0283 at 90 % confidence, 9 calibration blocks) among the arms that also pass the density rule R3 at the declared scored-truth mass.
  • Its density is checked against the metric's own algebra: 39,108 dots against the 86,541-dot wall that still allows a perfect-placement 0.3345; the ceiling for this density is 0.5588.
  • Its geology is not catalogue-proximity: multi-scale curvature and official edge layers, with no distance-to-known-fault feature anywhere in the stack.
